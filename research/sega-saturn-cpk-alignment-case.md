# 조사 사례: Sega FILM/Cinepak 검은 화면·반복과 정렬 누락

**증거 수준:** 실제 게임 재생 실패는 사용자 관측. 4바이트 정렬 훼손은 CPK 바이너리 측정으로 확인. 정렬 보정 뒤 실제 재생 문제가 완전히 해결되었는지는 **아직 사용자 런타임 재검수 대기**이므로 원인 후보를 확정적으로 단정하지 않는다.

## 재현된 차이

Sega Saturn 「슬램덩크」 DRT.CPK의 게임 사용자 검수에서 **검은 화면과 무한 반복**이 발생했다. 같은 게임의 원본 영상과 실패한 한글화 CPK를 검사하면 다음 차이가 나타난다.

| 검사 | 원본 | 실패한 재인코딩판 |
|---|---:|---:|
| STAB packet offsets 4바이트 정렬 | 2,129/2,129 | 568/2,129 |
| STAB packet sizes 4바이트 정렬 | 2,129/2,129 | 1,287/2,129 |
| Cinepak strip lengths 4바이트 정렬 | 3,362/3,362 | 1,906/3,362 |
| Sega physical-vs-declared frame size bias | 모든 영상 프레임 8 | 모든 영상 프레임 8 |

프로파일: 비디오 1,681프레임, PCM 448패킷, 영상 288×216, 15fps, 두 개의 108px Cinepak 스트립. 위 숫자는 **이 게임의 DRT.CPK에 한정**하며 모든 Saturn CPK에 그대로 일반화하지 않는다.

## 다른 프로젝트의 성공 패턴

「슬레이어즈 로얄」에서 사용한 정상 재패키징 절차는 각 Cinepak 청크(16비트 length)를 4바이트로 padding하고 길이를 갱신한 다음, 스트립(24비트 length)과 프레임(24비트 declared length)의 길이를 다시 기록하고 마지막으로 FILM/STAB offset·size를 재계산한다. PCM, PTS/duration 및 변경 금지 스트립을 보존하는 하이브리드 전략도 사용했다.

DRT의 초기 빌드는 FFmpeg/오프라인 전체 디코딩과 CPK 파일 크기 검증을 통과했으나, 정렬 검사 없이 테스트 디스크에 삽입했고 사용자 검수에서 실패했다. 이후 정렬 단계에서 **2,151개의 청크 padding, 영상 총 4,445바이트 추가, STAB 2,129/2,129 정렬**을 수행했으며, 원본 영상 1,681패킷을 해당 정렬 함수에 통과시켜도 원본과 바이트 단위로 동일하다는 no-op 회귀 검사를 했다.

정렬 수정본은 전체 1,681프레임의 이전 한글 영상과 디코딩 픽셀 동일, 448개 PCM 바이트 동일, FFmpeg strict decode PASS, 원본 BIN/CUE 변경 없음, 별도 ISO 및 xdelta 역적용 SHA 검증 PASS까지 확인했다. **정렬 수정본의 Saturn 게임 런타임 성공은 아직 입증되지 않았다.**

## 템플릿 차원에서 얻은 교훈

- PC 디코더가 관대하게 수용한 압축 파일을 실제 소비자(Saturn 게임)도 수용한다고 간주하지 않는다.
- 원본 매체의 **측정 가능한 구조 계약**을 사전에 수집하고, 최종 패키지에서 실패 시 빌드를 차단한다.
- 성공 사례의 방식은 참조하되 **프레임 수·스트립 높이·정렬 조건을 자동 이식하지 않는다**.
- 사용자가 실행 오류를 보고하면 정적 QA 녹색이었던 이전 빌드도 런타임 실패로 표시한다.
- 원본과 테스트 빌드는 보존하며 실패 원인과 수정판 검수 상태를 구별한다.
