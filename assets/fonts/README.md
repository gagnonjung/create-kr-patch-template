# 폰트 자산 구성

승인된 시각 목표, 문자 범위, 실제 소비 경로, 비용과 배포 조건에 맞는 글꼴을 채택한다. 기성 글꼴과 프로젝트에서 저작한 글꼴 모두 정확한 채택 결과를 식별해 제품 입력으로 관리한다.

## 원천과 교체

`sources/`에는 명시적으로 선택한 글꼴·글리프 자산 또는 사용자가 별도로 공급할 파일의 식별 정보를 둔다. 각 자산에 다음을 연결한다.

- 안정 ID와 정확한 파일의 강한 해시
- 출처·버전, 사용·수정·재배포 조건
- 프로젝트 저작물의 제작 도구·참조와 사람 승인 범위
- 공급 문자와 소비 경로, 크기·기준선·이진화·여백 등의 변환 입력

자형 보정과 변환은 식별 가능한 채택 원천을 기준으로 재현한다. 생성형 도구로 저작한 결과도 사람이 정확한 글리프 집합과 적용 범위를 채택하면 고정 입력으로 사용한다. 새 후보를 채택할 때에는 영향받는 시각 결정과 증거를 갱신한다.

`overrides/`는 국소 교체를 담는다. 문자 또는 안정 ID, 소비 경로, 교체 이유, 원천·권리와 필요한 승인 범위를 기록한다. 독립적으로 저작한 전체 글꼴은 `sources/`에서 관리한다. 별도 공급 자산은 빌드에서 실제 파일의 정체성을 검증한다.

## 빌드와 소비

채택 자산과 변환 규칙으로 래스터화·보정·패킹 결과를 재현한다. 문자 매핑은 명시적으로 관리하며, 현재 입력에서 파생할 경우 같은 빌드에서 결정적으로 생성한다. 번역 인코딩, 글리프 변환과 검증은 동일한 매핑을 소비한다.

빌드 보고서는 사용한 자산·교체·변환·매핑을 식별한다. 필요한 문자 공급과 매핑이 누락되거나 표시가 필요한 글리프가 비어 있으면 빌드를 실패시킨다. 공백처럼 의도적으로 픽셀이 없는 문자는 선언한 표시 동작으로 검증한다.

런타임 조합을 채택하면 선택한 글리프 결과와의 일치, 실제 소비 경로와 자원 수명을 검증한다. 생성형 저작은 후보 제작 단계에 두며, 반복 빌드는 채택 결과와 결정적인 변환을 사용한다.
